## Top gaps (ranked by user/business impact)
1. FR-5.2 Metadata-driven forms (with FR-5.3 grid): only a create form over `fakeCatalog()` exists, so every entity still needs hand-written list and detail screens. This blocks the "no hand-written UI" promise and slows every later wave. L.
2. FR-7.10 Protected-field approval: only credit limit is held for approval. Vendor bank account, remit-to, tax registration and payment-term changes apply straight away, which leaves the classic AP fraud path open. M.
3. FR-2.9 / FR-2.5 / FR-6.10 Legal-entity-scoped authorization: authz.rego has no legal-entity rule and scoped assignments are left out of the bundle, so a per-company role grants nothing in OPA. Roles are still bare duties, with no privileges or field masks. M.
4. FR-7.5 + FR-7.11 Duplicate check on create, and stewardship queue: the scoring engine exists but never runs on create or update, and there is no queue. The web Duplicates page needs two UUIDs typed in. Master-data quality decays from day one. M.
5. FR-5.12 Audit viewer (with FR-5.10 CDC capture and the FR-5.11 anchor): there is no History panel or audit workspace, capture is HTTP ingest only, and the change chain has no verify or anchor. Auditors cannot see who changed what. M.
6. FR-4.10 Job monitor + FR-4.9 cron scheduling: the job monitor, the workflow home and the designer show hard-coded sample data. There is no run list, cancel, hold or rerun API, and the cron fields are stored but never scheduled. Operators cannot run or watch batch work. M.
7. FR-10.13 PII handling in staging (Must): there is no staging schema, no per-project encryption, no retention purge and no `pii.read` filter on exception exports. This is a compliance blocker for real customer migrations. M.
8. FR-7.7 Electronic addresses: there is no email, phone, URL or fax on parties at all. Notifications, portals and the duplicate-detection blocking keys all depend on it. S.
9. FR-3.7 Lifecycle hooks: hooks are parsed but never executed, which also blocks server field validation (FR-5.6) and `rules.eval` from hooks (FR-3.13). L.
10. FR-7.9 / FR-7.15 Payment terms and installments: there is no term-create API, no due-date computation, no delivery terms or Incoterms, and no installment schedules. AP and AR due dates (waves 19, 30) have nothing to call. M.
11. FR-4.8 Workflow designer: the designer is a static picture and approval chains can only be posted as JSON. Administrators cannot configure approvals without help. M.
12. FR-8.1 / FR-5.8 Number sequences wiring: product numbers are typed in by hand (the `PROD` sequence is not wired), and there is no screen to maintain sequences. S.
