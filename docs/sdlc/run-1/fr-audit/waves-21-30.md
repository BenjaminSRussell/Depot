## Top gaps (ranked by user/business impact)
1. FR-28.4 Packing slip posting (also FR-28.5, FR-28.12): posting a slip creates no inventory issue and books no GL journal, so on-hand never drops, COGS/DNI never reach the ledger and AC-28.1/28.2 fail. Wire inventory issue-claims to a real issue plus ledgerclient (saga later). L.
2. FR-27.4 Cumulative ATP (also FR-27.3, FR-27.13, FR-27.17, FR-27.6): there is no stored atp_bucket projection, so every promise, alternative and backorder run works on buckets the user types in. Customers get no dependable promise date. L.
3. FR-22.3 Netting inputs (also FR-22.5, FR-22.8): MRP runs on a JSON snapshot pasted into the run form instead of reading sales, on-hand, POs and production orders. Planners can't run MRP for real. L.
4. FR-27.2 Sales orders / FR-27.9 change re-pricing: order lines take typed prices and ids. The w26 resolver, which is built and tested, is never called, and there are no customer or product pickers. Order entry is error-prone. M.
5. FR-29.1 Invoice from shipment (also FR-29.2): there is no packing-slip.posted consumer, and the clerk retypes slip lines with price, tax code and account. Shipped goods can go unbilled. M.
6. FR-21.5 / FR-21.7 production picking and RAF: no inventory transactions (w16), so consumption and finished goods never move stock, and costs come from the request. Breaks plant-floor inventory accuracy. M.
7. FR-29.6 Tax (with FR-29.3): invoices are taxed from an interim env rate table, not the w13 tax engine, and posting isn't atomic with the journal and open item. A compliance risk on every invoice. M.
8. FR-26.11 rebate accrual feed + FR-30.12 rebate settlement (Must, Not built): accruals need a manual endpoint call (no invoice.posted consumer) and nothing settles them, so the rebate liability cycle is open. M.
9. FR-30.16 SEPA direct debit mandates and collection (Must, Not built): no mandates, no pain.008 runs, so EU customers have no direct-debit collection. M.
10. FR-30.15 Phase-exit simulation (Must, Not built): there is no sim/phase5-month harness, so Phase 3–5 reconciliation can't be shown. The accountant sign-off then goes to #512. M.
