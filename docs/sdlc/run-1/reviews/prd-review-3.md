## Systematic observations
1. **Composite-condition clauses are still graded on the happy path.** FR-14.2 ("every module row closed or absent", "GL last") and FR-19.6 ("omitted when IBAN-only SEPA and profile allows") both have an implementation that covers the main case. Each drops one leg of the condition, and no test exercises that leg. *How to find:* for each remaining Built row whose FR or note text has "only when", "requires every", "omitted when … and …" or "last", find the test case for the negative leg. If none exists, read the predicate.
2. **"Any environment / any pack / any …" scope clauses.** In FR-1.10 the tool covers 2 of 3 environments and 1 service. Check the enumerations (`choices=`, maps of environments) against deploy/envs.
3. **Downgrades read only the API layer.** FR-6.16 was downgraded from the API pre-parse and its fake-store test, while the store enforces the rule. A downgrade must check the store/domain path before saying a validation is missing.
4. **PRD self-contradictions** (FR-6.1 4–8 vs `org.le.code_pattern` 2–8) and **stale NI rows** (receivables NI:85, finreport NI:35, inventory NI:575, receivables NI:41 GL half) go to stage 2 for fixes.
